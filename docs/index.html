In short

Given the current frame and the robot’s actions, a world model predicts the future video. We split that job in two: a learned simulator predicts how 3D scene points respond to the robot, and a video model renders the prediction.

The two meet in a pixel-aligned point dynamics proxy. Explicit point dynamics make object interaction more faithful: on DROID with two video renderers of different architectures, without degrading image quality, and on a real bimanual robot. Swap in a better simulator and the video gets better.

The problem

The arm follows the actions. The objects do not.

Given the current frame and a sequence of robot actions, a robotic world model predicts the future video. Rendering the robot into the input makes the arm follow the actions, but the objects in contact still go wrong: they collapse, or respond inconsistently with the action.

DROID test clips, Wan2.2. Dashed boxes mark the object in the last third of the clip. Videos play at half speed.

Insight

Separate what happens from how it looks.

An action, numeric or rendered, specifies where the robot goes but not how the scene responds. A single video model must then infer the interaction dynamics while also rendering appearance.

Following code world models [1, 2, 3], we split the two jobs. A simulator evolves the world state and draws it into a coarse proxy video; the video model paints the final frames from it. For robot manipulation, the central design choice is the proxy.

What should the proxy be?

The proxy must represent any object, including deformable and articulated ones. It must be obtainable from a single real observation, and its dynamics must be predictable under robot actions.

✗Physics simulator

Needs mass, friction, object meshes and a solver for each material, all of which are hard to obtain in a real scene.

✗Hand-written rules

A rule written as code can move the object held between the fingers, but cannot express pushing, dragging or deformation.

✓3D point dynamics

From one RGB-D frame, points represent any object, rigid or deformable. Their dynamics are learned from real robot data.

Method

Simulate in 3D. Render back to 2D.

The simulator decides what happens; the video model decides how it looks. They meet in a pixel-aligned proxy. Scroll through the four steps on the clip of the paper’s method figure.

  1. 1

    Lift to 3D

    The first RGB-D frame becomes scene points; forward kinematics turns the actions into robot points.

  2. 2

    Simulate

    A learned point dynamics model, PointWorld [4], predicts how every scene point responds to the robot.

  3. 3

    Proxy

    The simulated points are drawn back into pixel-aligned videos: robot render, warp of the first frame, and point tracks.

  4. 4

    Render

    A video model reads the proxy through its own VAE and paints the real arm, lighting and contact.

Results

Same frame. Same actions. Different conditions.

Every model starts from the same first frame and receives the same actions; only the conditioning differs. Without point dynamics, the arm moves correctly but the object does not. With the point dynamics proxy, the object responds as in the real video.

Experiments

What the numbers say.

Data
DROID: 326K training clips; 1,515 test clips from 900 held-out episodes in 13 labs. No wrist camera, no text.
Renderers
Wan2.2 (DiT) and Ctrl-World (SVD UNet), each trained with four conditions on the same data and budget.
Metric
Object motion error: object points are tracked in the generated and the real video; the pixel distance between the tracks. Lower is better.

Conclusion

Better point dynamics, more faithful world models.

We decouple a robotic world model into a simulator that predicts how 3D scene points respond to the robot and a renderer that turns the prediction into video, connected by a pixel-aligned point dynamics proxy. Explicit point dynamics make object interaction more faithful, and the video follows the simulator. Progress in 3D point dynamics, learned or written as code, can thus carry over to robotic world models without changing how they render.
